# Cross-project OCR experience and research backlog

This clean-room synthesis informs the shared lab without copying private code, private documents, or private experiment logs. A finding from another engine, an Android emulator or host benchmark is **not** proof of improved OCR on this corpus. The private predecessor projects were reviewed internally; their observations below are generalized, not public reproducible evidence. Public sources are linked directly. Prefer falsifiable experiments to rediscovering known failure modes.

## Acceptance protocol

1. Each experiment has exact candidate configuration, engine/model versions, input hashes, independent truth, fixed settings and a baseline. Negative results remain in the ledger. Never relabel a timeout as a recognition failure.
2. Raw OCR CER, field-presence hits, role/rectangle/type accuracy, false automatic accepts, abstention/review, and cost are separate measures. The current paired corpus measures field presence only. For every later field/geometry benchmark report TP/FP/FN, F1, page coverage, one-to-one matches, and per-field evidence; do not optimize an aggregate alone.
3. Split by underlying document, not capture mode, page or re-render. This five-page statement is a development/regression document, not an independent holdout. Add new synthetic and independently authorized real documents before making generalization claims.
4. Synthetic dev and validation cohorts cannot regress; a paired candidate must add at least one exact expected field without losing any existing exact field on either modality. Promotion stays a lab candidate, even if the whole corpus reaches 44/44.
5. Preserve offline operation and test actual Android ML Kit integration, label roles, multi-page capture and device memory before an app release. Don't send raw app captures back to the public lab.

## Next implementation order

### P0 — Improve the existing ML Kit pipelines before changing engines

Tesseract is a historical CPU control. Both current apps already ship the same bundled ML Kit Latin SDK 16.0.1; the research target is that existing engine, not a replacement or extra OCR dependency. [Umliva dependency evidence](https://github.com/xxammaxx/Umliva_2.0/blob/b215be89564c727b1a84cd4b0bf597fa8dcadd19/docs/dependency-review.md) and [Feldexa Gradle pin](https://github.com/xxammaxx/Feldexa_2.0/blob/2a1452b378660940d70f99f0ead88da6a933da28/apps/feldexa_app/android/app/build.gradle.kts). The standalone harness is an Android API 35 x86_64 emulator benchmark, not a replacement app or production adapter.

1. Compare raw baseline, 1% contrast, sharpening, autocontrast, thresholding and scaling using the existing bundled SDK. Umliva uses even-padded NV21 BT.601 Y/V/U, Feldexa uses gray8 to opaque ARGB. Keep paired photo/scan measurements separate from synthetic dev and validation. Use one novel variant per CI night; run each against a fresh control on both paths.
2. Test input scale, localized deskew, low contrast, blur, rotation, cropped regions, single/targeted multiple passes and per-page failure isolation. Record raw spelling and exact German critical field hits; no blanket OCR confusable replacement.
3. Add coordinate/role truth, especially tables and monetary fields, and measure false accepts, review, coverage, latency and memory on the actual production adapter. The current harness scores field presence and synthetic CER, not role accuracy or target device memory.
4. Keep alternative engines as documentary prior art only. No PaddleOCR, Tesseract or another engine/model as a new dependency in the apps or autonomous optimization target unless a separate future decision authorizes it. Preserve offline ML Kit inference and app-specific independent acceptance.

P0 takes priority over all reference-engine tuning. P1/P2/P3 follow with the same ML Kit target. Run small discriminating experiments and add a regression whenever a concrete fault is found. The scheduled loop has a finite ML Kit catalogue and records rejection rather than auto-merging app changes. Prior findings change its search priorities, not the acceptance standard.
