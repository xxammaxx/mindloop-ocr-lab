# Cross-project OCR experience and research backlog

This clean-room synthesis informs the shared lab without copying private code, private documents, or private experiment logs. A finding from another engine, an Android emulator or host benchmark is **not** proof of improved OCR on this corpus. The private predecessor projects were reviewed internally; their observations below are generalized, not public reproducible evidence. Public sources are linked directly. Prefer falsifiable experiments to rediscovering known failure modes.

## Acceptance protocol

1. Each experiment has exact candidate configuration, engine/model versions, input hashes, independent truth, fixed settings and a baseline. Negative results remain in the ledger. Never relabel a timeout as a recognition failure.
2. Raw OCR CER, field-presence hits, role/rectangle/type accuracy, false automatic accepts, abstention/review, and cost are separate measures. The current paired corpus measures field presence only. For every later field/geometry benchmark report TP/FP/FN, F1, page coverage, one-to-one matches, and per-field evidence; do not optimize an aggregate alone.
3. Split by underlying document, not capture mode, page or re-render. This five-page statement is a development/regression document, not an independent holdout. Add new synthetic and independently authorized real documents before making generalization claims.
4. Synthetic dev and validation cohorts cannot regress; a paired candidate must add at least one exact expected field without losing any existing exact field on either modality. Promotion stays a lab candidate, even if the whole corpus reaches 44/44.
5. Preserve offline operation and test actual Android ML Kit integration, label roles, multi-page capture and device memory before an app release. Don't send raw app captures back to the public lab.

## Next implementation order

### P0 — Compare engines before further tuning

Tesseract is a reproducible CPU control, not the selected production engine. ML Kit is the existing on-device comparator from our app work. Prior local vision-model experiments did not establish a general accuracy advantage. Do not infer the winning engine from model age, vendor scores or one easy synthetic sheet.

1. Compare the control against a modern compact multilingual neural recognizer: [PaddleOCR PP-OCRv6](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html) (German, CPU/ONNX), and its mobile-sized tier. [RapidOCR](https://github.com/RapidAI/RapidOCR) is a possible ONNX deployment route, not independent evidence of a different model architecture. Pin code, exact German-capable weights, hashes and model licenses before execution.
2. Reproduce bundled [Android ML Kit Text Recognition v2](https://developers.google.com/ml-kit/vision/text-recognition/v2/android) on the same corpus via a bounded emulator/device adapter; compare target latency and memory separately from Linux host metrics.
3. If the first two comparisons warrant it, screen [docTR](https://mindee.github.io/doctr/latest/user_guide/ocr_predictor.html) with verified multilingual vocabulary and a compact local document vision model in shadow mode. No remote image inference, paid runners, or automatic model fine-tuning. Larger models must first fit a measured CPU/memory budget.
4. Use the same field truth and pixel inputs, preserve OCR lines and polygons for role/geometry tests, and compare paired hit indices, Unicode confusions, false accepts, abstentions, per-page elapsed time, peak RSS and model size. Keep each engine's runtime/model identity distinct. Check German glyph coverage independently. Do not promote until the app-specific offline target passes.

P0 takes priority over expanding the existing Tesseract filter catalogue. P1/P2/P3 follow as engine-independent research streams. Run small discriminating experiments before adding complicated pipelines, and add a regression whenever a concrete fault is found. The scheduled CPU loop has a finite reference catalogue and will record rejection rather than auto-merge app changes. Prior findings change its search priorities, not the acceptance standard.
